The brand name in the product: hardcoded or tokenized

Hardcoded
The brand name is written directly into the product, in the header, the templates, the emails. Today this is Campminder, everywhere.
Tokenized
The product pulls the brand name from one setting. One codebase can show UltraCamp to an UltraCamp customer and Campminder to a Campminder customer.

This sets whether the platform can ever carry more than one brand, and it changes the cost of keeping UltraCamp as a brand rather than folding it in. The window to choose cheaply is the current rebuild. After that it becomes its own project.

Studio Parkside recommendation

Tokenize the brand name during the rebuild, so the brand call is made on whether a brand is worth keeping rather than on what the code makes expensive.

Either answer is valid. The point of recording it here is that it is a conscious call, made by an owner, rather than one that gets decided by default while the rebuild ships.
